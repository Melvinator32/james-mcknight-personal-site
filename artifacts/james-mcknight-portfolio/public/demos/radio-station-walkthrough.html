Tuned In

A five-minute walkthrough of the demo

Tuned In is a personal productivity system — a task board that knows what the work is for. It tracks tasks, but it also tracks the goals those tasks serve, the skills you're building, and what the work actually feels like day to day.

The demo is the real application running entirely inside your browser. Every button works. Nothing is saved anywhere, and nothing is sent anywhere — refresh the page and it returns to how it started, so click freely.

In one sentence

Most to-do apps optimise for throughput — capture everything, finish everything. This one optimises for direction: whether the work you finished added up to anything.

The one idea to understand first

In most apps, you decide which list a task belongs in. Here, you set a status and the app files the task for you. The board's groups aren't folders you maintain — they're the visible result of rules you control.

Try this first — it takes ten seconds

On the Table tab, find the task called “Try changing a Status — watch the task move groups.” Click its Status cell and choose Holding Pattern.

The task disappears from All Active Tasks and reappears further down under Holding Pattern / Pending. Set it back to Working On It and it returns. Nothing was dragged.

The rules driving that live under Edit → Automations, and they're fully editable.

A guided tour

Four stops, in the order that builds on itself.

  1. The board Table

    Eight groups, and every column is user-defined — text, status, person, date, number, priority, checkbox. Click any cell to edit it in place.

    Two columns are worth noticing. Values and Goal connect a task to what it's for; tag a goal and its value fills itself in. At the far right, Win and Loss close out an outcome — marking a Loss files that task and its goals into an Improvements list, so misses land somewhere instead of evaporating.

    Open Build the pricing scenario model with the arrow on its left to see subtasks; finished ones collapse out of the way and can be brought back.

  2. Deciding what matters Matrix

    The Eisenhower square: urgent versus important. Drag tasks between Do First, Schedule, Delegate and Eliminate, and give each a time estimate in fifteen-minute steps. Each quadrant totals its own time.

  3. Making the day Today

    Three meetings are already on the schedule. Press ⚡ Auto-plan day.

    It fills the gaps around those meetings using the Matrix order — Do First, then Schedule, then Delegate, with Eliminate skipped — and gives each task the time you estimated. Auto-planned blocks are marked, so re-running replaces them instead of stacking, and Clear auto-plan removes only those, leaving meetings alone.

  4. What the work is for Goals

    This is the part that makes it more than a task list, so it's worth a minute.

    Goals live inside Values — Craft & Quality, Judgment, Reach & Influence, Self-Investment, Future Options. A goal isn't a checkbox: it's measured by the tasks tagged to it, so you never update one by hand.

How tasks connect to goals

Every other view feeds this one. The loop has five steps, and you can follow all of them in the demo.

  1. Write a goal under a value

    On Goals, each card sits in a value. “Writing that carries a decision” lives under Craft & Quality, with a plan and, optionally, a number to hit — that one is tracked at 3 of 12 memos.

  2. Tag a task to it Table

    Back on the board, the Goal column links a task to a goal. Draft the quarterly summary is tagged to that writing goal.

    Notice what happens to the Values column beside it: tag a goal and its value fills itself in. The two columns can't drift apart, and you only ever make one decision.

  3. Finish the task, and the goal moves

    Set that task to Done. The automation files it into the Done group and stamps today's date — and the goal's progress bar moves, because progress is the share of its tagged tasks that are finished. “Writing that carries a decision” currently reads 25% off four tagged tasks.

    Nothing was self-reported. The goal moved because work moved.

  4. See it counted against a level

    The strip at the top of Goals is the payoff: completed work by role expectation, Analyst through VP. Each goal carries a level, so finishing a tagged task credits that level automatically.

    Two numbers per card, and the second is the useful one. Done is volume. Expectations covered is spread — four finished tasks all serving one expectation reads as busy, not as ready. Click a level to filter the whole page to it.

  5. Open a goal to close the loop

    Click any goal. You get its plan, its progress, and every task advancing it, finished ones ticked. There's a search box to tag more tasks without leaving the page, and a running count of how many are tagged versus done.

    In the full application this is also where a scorecard exports — every expectation with the tasks that evidence it, which is the document you'd take into a review.

Why it's built this way

Goal tracking usually fails because it's a second system: you do the work in one place and report on it in another, and the reporting rots. Here there is no second system. The goal is a query over tasks you were going to move anyway — so the only way to make progress look good is to actually do the work.

The other two tabs

  • Kanban — the same tasks as columns by status. Drag between columns and the automations fire exactly as they do on the board.
  • Skill Lab — what you're learning, tracked like a project: reading progress by page or minute, a “1% better today” streak, and a Today-I-Learned log. Tasks from the board can be filed under a skill, so it shows what you're actually practising.
Not in this demo

The full application also has a Notebook (notes, ideas, prompts, side projects, and a career-observation log), PARA for organising projects and reference material, a Rewards system that pays out points for finished work, a Zen Garden whose raked-sand patterns are generated rather than drawn, and three more Goals views — a mind map, an improvements log, and a personal operating system. They hold long-form writing rather than anything you could try in five minutes, so they're left out here.

One more thing to try

The Dark button at the top right of the banner switches the whole app between a light ground and a Wet Slate dark one. The palette is the same either way — beach tones, slate, driftwood and jade — and the wood banner is repainted rather than recoloured, so its grain changes with the ground.

If you're looking at how it's built

Tuned In is Flask and SQLite with a vanilla-JavaScript front end — no framework, no build step, about fourteen thousand lines. It runs locally; there's no account and no server to talk to.

This demo has no backend at all. A portfolio page is static, so the Flask API is replaced by an in-memory implementation in the browser that answers the same routes. The interface code is unchanged — only its server is different.

The automation engine was ported rather than faked, which is why the status change in the first exercise behaves exactly as it does in the real application, including copying tasks between groups and collapsing duplicates when something is completed.

Worth repeating
